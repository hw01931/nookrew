# 기술 문서

## 원칙
- 읽는 사람과 목적을 먼저 정한다(처음 쓰는 사람인가, 고치는 사람인가).
- 할 일 순서대로, 실제로 돌아가는 예시와 함께.
- 코드가 말하는 것은 반복하지 않고 "왜"와 계약(입력·출력·오류)을 쓴다.
- 짧은 문단, 제목, 목록. 확인하지 않은 것은 확인하지 않았다고 쓴다.

## 종류별
- README: 무엇인지, 실행법, 구조 한 단락, 알려진 한계.
- 변경 기록: 무엇이 바뀌었고 사용자가 할 일이 있는가.
- 인계: 진행 상황, 결정, 남은 일, 참고 위치.
