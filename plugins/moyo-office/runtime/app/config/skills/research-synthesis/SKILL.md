# 조사 결과 정리

## 자료
사용자가 준 원자료만 쓴다: 인터뷰 기록, 설문 결과(sheet), 사용성 시험 메모, 문의·피드백 기록(record.search kind feedback·message), 앱 리뷰(web.fetch, 주소 남김). 원자료가 없으면 정리하지 않고 요청한다.

## 정직 규칙
- **인용은 원문 그대로만, 참여자 번호(P1)와 함께.** 고쳐 쓰거나 지어내지 않는다.
- 관찰과 해석을 나눈다: "8명 중 5명이 다른 버튼을 눌렀다"(관찰) / "버튼 위치가 헷갈린다"(해석).
- 셀 수 있으면 센다: "대부분" 대신 "10명 중 7명". 직접 센 것만 쓴다.
- 적은 표본·편향된 모집은 한계로 적는다. 설문 수치는 표본 크기와 함께.

## 순서
1. 원자료를 읽고 관찰 하나를 한 줄로 뽑는다(누가 · 무엇을 · 출처 위치).
2. 비슷한 관찰을 묶어 주제를 만든다(친화도 묶기). 주제 이름은 사용자 입장의 문장으로.
3. 주제마다: 몇 명에게서 나왔나, 근거 인용 2개 이상, 제품에 주는 의미.
4. 인사이트 → 기회: 무엇을 배웠고 무엇을 할 수 있나, 영향과 노력(높음/중간/낮음).
5. 사용자 유형이 보이면 특징·필요를 정리한다(규모는 센 수만).
6. 아직 모르는 것과 다음 조사 질문.

## 결과(artifact.write type report)

```
## 조사 정리: [이름]
방법 · 참여자 수 · 기간
### 요약 (3~4문장)
### 주제
#### 주제 1: [이름]
빈도: Y명 중 X명
내용:
근거: "인용" — P3 / "인용" — P5
의미:
### 인사이트 → 기회 (표: 인사이트 · 기회 · 영향 · 노력)
### 사용자 유형 (있으면)
### 제안 (우선순위와 근거 주제)
### 더 알아볼 것
### 방법과 한계
```

여정 지도가 도움이 되면 artifact.write type diagram(flowchart나 journey)으로 그린다. 제안을 업무로 옮길 때는 사용자 확인 후 work.write.
