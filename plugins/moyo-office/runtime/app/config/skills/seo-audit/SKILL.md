# 검색 최적화(SEO) 점검

## 입력
주소(또는 주제), 점검 종류(전체 / 핵심어 / 콘텐츠 빈틈 / 기술 / 경쟁사 비교, 기본은 전체), 노리는 핵심어, 경쟁사.

## 할 수 있는 것과 없는 것
- web.fetch로 공개 페이지의 글자를 읽을 수 있다. 검색량·난이도·순위·백링크 수는 볼 수 없다.
- **검색량·순위·속도 점수를 지어내지 않는다.** 수요는 근거(검색 결과에 경쟁 글이 많음 등)와 함께 높음/중간/낮음 "추정"으로만 쓴다.
- 확인 못 한 항목은 표에 "확인 못 함"으로 둔다. 속도·모바일 점수는 사용자에게 측정 도구 결과를 요청한다.

## 1. 핵심어
주 핵심어(제품과 직결), 보조어, 긴 꼬리 질문("~하는 법", "~란"), 의도(정보 / 탐색 / 비교 / 구매). web.search 결과에서 실제로 보이는 경쟁 글을 근거로 쓴다.

## 2. 페이지 점검(주요 페이지마다 web.fetch)
- 제목: 있음, 페이지마다 다름, 짧음(대략 60자 이내), 핵심어 포함.
- 설명(meta description): 있음, 행동 유도, 대략 160자 이내.
- 큰 제목(H1)은 하나, 소제목 순서가 논리적.
- 첫 문단에 핵심어, 억지 반복 없음.
- 내부 링크와 설명적인 링크 문구, 이미지 대체 텍스트, 짧고 읽히는 주소.
- 읽은 글자에 meta 정보가 없으면 "본문만 확인"으로 적는다.

## 3. 콘텐츠 빈틈
경쟁사가 다루고 우리는 없는 주제, 오래된 페이지, 내용이 얇은 페이지, 없는 형식(가이드·비교·용어집), 구매 단계별 빈 곳, 주제 묶음(중심 글 + 보조 글) 기회.

## 4. 기술 항목
robots.txt와 sitemap 존재(web.fetch로 확인), https, 깨진 링크(읽다가 발견한 것), 중복 페이지·canonical, 구조화 데이터 기회(FAQ·Article·Product), 모바일 대응.

## 5. 경쟁사 비교
같은 핵심어로 검색했을 때 누가 보이는가, 콘텐츠 깊이·형식·갱신 빈도.

## 결과(artifact.write type report, 큰 표는 type sheet)
- 요약 3~5문장: 가장 큰 강점, 우선순위 3가지, 전체 판단
- 핵심어 후보 표: 핵심어 · 의도 · 수요(추정) · 추천 콘텐츠 형식 · 근거
- 페이지 문제 표: 페이지 · 문제 · 심각도(치명/높음/중간/낮음) · 고치는 법
- 콘텐츠 빈틈 제안: 주제 · 이유 · 형식 · 우선순위 · 노력
- 기술 점검표: 항목 · 통과/실패/주의/확인 못 함 · 내용
- 실행 계획: 바로 할 것(제목·설명·대체 텍스트·깨진 링크) / 장기 투자
- 출처 주소 목록
