# 일일 보고(스탠드업)

## 핵심 규칙
**기록에 있는 것만 쓴다.** 업무 상태, 완료, 검증 결과, 진행률을 추측하거나 만들어 채우지 않는다. 기록이 없으면 "기록 없음"이라고 쓴다. 조용한 날의 보고가 짧은 것은 정상이다.

## 1. 기간 정하기
- 이전 보고를 찾는다: record.search {query:"일일 보고", kind:"artifact"}. 있으면 그 뒤부터, 없으면 최근 하루를 본다.
- 보고 첫 줄에 기간을 적는다("10/6 09:00 이후 기록 기준").

## 2. 기록 모으기
- 업무: record.search kind work로 상태가 바뀌었거나 새로 생긴 업무.
- 산출물·수정안: kind artifact, 수정안과 검증 결과(검증 실행 기록이 있는 것만 PASS/FAIL로 쓴다).
- 결정: kind decision(제안인지 사용자가 확정했는지 구분).
- 대화·회의: kind message, meeting에서 막힘·요청·질문.
- 필요한 것만 record.read로 원문을 읽는다. 모든 기록을 읽지 않는다.

## 3. 분류
- 한 일: 완료·제출·결정된 것. 기록 ID를 붙인다.
- 다음 할 일: 진행 중이거나 다음 차례인 업무(기록의 상태·선행 조건 기준). 예정이 기록에 없으면 "예정 기록 없음".
- 막힌 것: 실패한 검증, 사용자 결정 대기, 선행 업무 미완료, 권한·예산 부족, 답이 없는 질문. 누구의 무엇이 필요한지 적는다.
- 상태를 모르면 "확인 필요"로 둔다. 응답이 끝난 것을 완료로, 시작한 것을 진행으로 바꿔 쓰지 않는다.

## 결과
artifact.write type report, 제목 "일일 보고 YYYY-MM-DD":

```
기간: …
## 한 일
- [업무 제목] 무엇이 됐는가 (기록 ID)
## 다음 할 일
- …
## 막힌 것
- 무엇 · 필요한 것 · 누가 (기록 ID)
## 확인 필요
- …
```

짧게 쓴다. 한 항목 한 줄. 사용자가 바로 볼 것(막힌 것, 결정 대기)을 빼먹지 않는다.
