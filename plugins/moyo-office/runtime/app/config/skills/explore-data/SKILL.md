# 데이터 살펴보기

## 1. 읽기
sheet 산출물은 record.read, 프로젝트 파일은 project.read(권한이 있을 때). 크면 앞부분과 끝부분을 먼저 본다. 전부 읽지 못했으면 "앞 N행만 봄"이라고 적는다.

## 2. 구조
- 행·열 수, 한 행이 무엇 하나인가(예: 주문 1건), 고유 키가 정말 고유한가, 기간 범위.
- 열 분류: 식별자 / 분류(상태·지역) / 수치(금액·횟수) / 날짜 / 자유 글 / 참·거짓.

## 3. 열별 요약
- 모든 열: 빈 값 수·비율, 서로 다른 값 수, 가장 흔한 값 5개.
- 수치: 최소·최대·평균·중앙값, 0과 음수 개수.
- 글: 길이, 빈 문자열, 형식이 일정한가, 대소문자·앞뒤 공백.
- 날짜: 처음·마지막, 미래 날짜, 빠진 기간.
- 직접 센 것만 숫자로 쓴다. 표가 크면 sheet 수식(COUNTBLANK, COUNTIF 등)으로 두고 "수식 결과 확인 필요"로 표시한다.

## 4. 품질 문제 찾기
- 빈 값: 5% 넘으면 주의, 20% 넘으면 경고.
- 자리 채움 값: 0, -1, 999999, "N/A", "없음", "test".
- 같은 뜻 다른 표기: "서울"/"서울시"/"Seoul".
- 규칙 위반: 음수 수량, 시작일보다 이른 종료일, 100% 넘는 비율, "완료"인데 완료일이 비어 있음.
- 중복 키, 한 값만 지나치게 많음(기본값 의심), 끝자리가 0·5뿐(추정치 의심).

## 5. 관계와 패턴
다른 표와 이을 키, 계층(시도 > 시군구), 함께 움직이는 수치(상관 ≠ 원인), 다른 열에서 계산된 열.

## 결과
artifact.write type report: 개요(행·열·기간), 열 요약 표, 품질 문제(심각도 높음/중간/낮음), 분석에 쓸 만한 기준·지표, 다음에 할 분석 3~5개. 표 정리가 필요하면 type sheet.
