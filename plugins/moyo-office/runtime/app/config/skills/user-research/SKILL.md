# 사용자 조사

## 정직 규칙
직원은 사용자를 직접 인터뷰하거나 설문을 돌릴 수 없다. 계획·질문지·분석 틀을 만들고, 실제 조사는 사람이 한다. **참여자 발언, 설문 결과, 관찰 내용을 지어내지 않는다.** 예시 응답이 필요하면 "가상 예시"라고 표시한다.

## 1. 조사 질문
무엇을 결정하려고 조사하는가 → 알아야 할 것 3~5개. 이미 아는 것(record.search로 이전 조사·피드백 기록)과 모르는 것을 나눈다.

## 2. 방법 고르기
| 방법 | 좋은 때 | 보통 규모 |
| --- | --- | --- |
| 인터뷰 | 필요·동기를 깊이 이해 | 5~8명 |
| 사용성 시험 | 특정 화면·흐름 평가 | 5~8명 |
| 설문 | 태도·선호를 수로 파악 | 100명 이상 |
| 카드 분류 | 메뉴·정보 구조 결정 | 15~30명 |
| 일지 조사 | 시간에 따른 행동 | 10~15명 |
| A/B 시험 | 두 디자인 비교 | 통계적으로 충분히 |
공개 자료(web.search·web.fetch)로 하는 2차 조사는 출처 주소를 남기고 1차 조사를 대신한다고 쓰지 않는다.

## 3. 인터뷰 가이드
1. 시작(5분): 목적 설명, 녹음 동의, 정답이 없다는 안내.
2. 맥락(10분): 지금 어떻게 하는가, 최근에 실제로 한 일.
3. 깊이(20분): 주제 질문. 열린 질문("어떻게 하셨어요?"), 유도 질문 금지("편하셨죠?"), 가정 질문보다 실제 경험("마지막으로 ~했던 때").
4. 반응(10분): 시안·흐름을 보여 주고 생각을 말하게 한다.
5. 마무리(5분): 빠진 것, 감사.
질문마다 더 물을 것(왜, 예를 들면)을 붙인다.

## 사용성 시험 과제
사용자 목표로 쓴다("업무 하나를 직원에게 맡겨 보세요"). 버튼 이름을 알려 주지 않는다. 과제마다 성공 기준, 관찰할 것(망설임·실수·되돌아감)을 정한다.

## 설문
한 문항에 한 가지만, 중립 표현, 척도 일관(1~5), 선택지 빠짐없이·겹치지 않게, 앞 문항이 뒤 문항을 유도하지 않게.

## 결과(artifact.write type plan)
조사 계획(목적, 질문, 방법, 대상과 모집 조건, 일정, 동의·개인정보 처리), 인터뷰 가이드 또는 과제·설문지, 분석 방법(research-synthesis 스킬). 일정이 있으면 work.write로 업무를 나눈다.
