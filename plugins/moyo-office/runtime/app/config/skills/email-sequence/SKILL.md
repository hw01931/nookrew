# 이메일 시퀀스

## 입력
종류(가입 안내 / 잠재 고객 육성 / 재참여 / 이탈 고객 복귀 / 출시 / 행사 후속 / 상위 요금제 / 교육), 목표, 받는 사람과 조건, 통 수·간격(없으면 아래 틀), 브랜드 말투(memory.search), 쓸 수 있는 혜택·링크·자료.

## 1. 전체 설계
- 흐름: 첫 통에서 마지막 통까지 어떤 이야기로 이어지는가.
- 통마다 단계(알기 → 고려 → 결정 → 사용 → 확장)를 정한다.
- 성공 정의: 어떤 행동을 하면 목표 달성으로 보고 시퀀스에서 빠지는가.

## 2. 통마다
- 제목 후보 2~3개(호기심·이점·질문 등 다르게, 짧게)와 미리보기 문구(제목 반복 금지).
- 이 통의 목적 한 문장.
- 본문: 첫 줄 → 내용 → 행동 유도. 짧은 문단, 개인화 자리({이름}).
- 주된 버튼 하나(문구와 연결 위치).
- 보낼 때(가입 후 며칠 / 이전 통 후 며칠)와 받을 대상 조건.

## 3. 흐름 규칙
- 분기: 열었지만 누르지 않음 → 부드러운 재안내, 눌렀음 → 다음 단계로 건너뜀.
- 종료: 목표 행동을 하면 즉시 제외.
- 다시 들어오기, 제외(수신 거부, 다른 시퀀스 진행 중, 최근 문의).
- 흐름도는 artifact.write type diagram(flowchart TD)으로 그린다.

## 기본 틀(조정해서 쓴다)
- 가입 안내 5~7통: 환영과 기대 → 빠른 첫 성공 → 핵심 기능 → 고급 기능 → 사례·커뮤니티 → 의견 요청 → 다음 단계
- 육성 4~6통: 유용한 정보 → 문제 짚기 → 해결책과 근거 → 사례 → 가벼운 제안 → 직접 제안
- 재참여 3~4통: 돌아올 이유 → 놓친 것 → 혜택 → 마감 안내
- 출시 4~6통: 예고 → 발표 → 기능 소개 → 초기 반응 → 기한 혜택 → 마지막 안내

## 정직 규칙
- 사례·후기·수치는 실제 근거가 있을 때만. 없으면 [확인 필요] 빈칸.
- 가짜 긴급함("오늘만!")은 실제 기한이 있을 때만.
- 열람률·전환율 기준치는 출처가 있을 때만 주소와 함께 쓴다. 없으면 "첫 발송 후 실제 수치로 목표를 정한다".
- 수신 거부 안내를 모든 통에 넣는다.

## 결과(artifact.write type report)
요약 표(번호 · 제목 · 목적 · 보낼 때 · 버튼 · 조건), 통별 전체 문안, 흐름도, 분기·종료·제외 규칙, A/B 시험 제안 2~3개(무엇을, 어떻게 나눠, 무엇으로 판정), 볼 지표, 아무 발송 도구에서나 따라 할 설정 순서(자동화 만들기 → 시작 조건 → 통·간격 → 분기·종료 → 측정).
