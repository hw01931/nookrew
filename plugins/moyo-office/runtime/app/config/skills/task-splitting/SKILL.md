# 업무 나누기

## 원칙
- 한 업무 = 혼자 끝내고 확인할 수 있는 크기. 완료 기준을 검증 기준 시험 이름 1~2개로 단다(criteria).
- 여러 직원이 나눠 할 때는 「인터페이스 정하기」 업무를 먼저 두고 나머지가 dependencies로 이어진다.
- 첫 업무는 화면 뼈대와 가장 기본 기능.
- 같은 파일을 동시에 고치는 업무를 나란히 두지 않는다(순서로 잇는다).

## 순서
1. 목표와 완료 기준을 다시 읽는다(프로젝트 목표, 검증 기준 시험 이름).
2. 의존 관계를 Mermaid flowchart로 먼저 그려 본다(선택).
3. work.write로 업무를 만든다: title, goal(무엇을, 완료 기준), assigneeId, criteria, dependencies(앞 업무 title).
4. 빠진 시험 없이 모든 시험이 한 업무에 하나씩 들어갔는지 확인한다.
