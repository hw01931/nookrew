# 기술 부채

## 종류
| 종류 | 예 | 위험 |
| --- | --- | --- |
| 코드 | 중복된 처리, 이름만 있는 숫자, 너무 긴 함수 | 버그, 느린 개발 |
| 구조 | 섞인 책임, 맞지 않는 저장 방식, 순환 의존 | 바꾸기 어려움 |
| 시험 | 없는 시험, 가끔 실패하는 시험 | 회귀 |
| 의존성 | 오래된·관리 안 되는 라이브러리 | 보안 취약점 |
| 문서 | 낡은 README, 사람 머릿속에만 있는 지식 | 인계 어려움 |
| 운영 | 수동 배포, 감시 없음 | 장애, 느린 복구 |

## 찾기
- project.search로 근거를 모은다: TODO·FIXME, 같은 문자열·정책 반복, 빈 catch, 큰 파일, 시험 없는 모듈.
- record.search로 반복된 버그·실패한 검증·되돌린 수정안을 찾는다(같은 곳이 자주 깨지는가).
- 항목마다 근거(파일:줄 또는 기록 ID)를 단다. 근거 없는 "느낌"은 쓰지 않는다.

## 점수
- 영향: 개발을 얼마나 늦추나 (1~5)
- 위험: 안 고치면 무슨 일이 나나 (1~5)
- 노력: 고치기 얼마나 어려운가 (1~5, 낮을수록 먼저)
- 우선순위 = (영향 + 위험) × (6 − 노력)
점수는 판단이다. 이유를 한 줄 붙인다.

## 결과
artifact.write type report: 항목 표(내용 · 종류 · 근거 · 영향 · 위험 · 노력 · 우선순위 · 이유), 단계별 계획(기능 작업과 함께 할 수 있게 작은 단위로). 바로 할 것은 work.write로 업무를 만들고, 각 업무에 확인할 시험을 단다. 고치는 동작이 바뀌지 않음을 시험으로 먼저 고정한다.
