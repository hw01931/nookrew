# Codex에서 사무실 사용하기

현재는 Windows x64용 설치 파일과 소스 실행을 제공한다. Codex 대화 영역을 교체하지 않고 로컬 사무실을 내장 브라우저에서 연다. 공식 마켓플레이스에 게시한 플러그인은 아니다.

## Windows 설치 파일로 시작

1. `release/office/AIOrchestra-Office-Setup-0.1.0.exe`를 실행해 현재 사용자 계정에 설치한다. Node.js·npm·별도 모델·API 키는 필요 없다. 내장 Node 22.15.1과 런타임 의존성을 포함한다.
2. 설치 후 **AI오케스트라 사무실** 바로가기를 실행하고, Codex에서 사용하는 프로젝트 폴더를 고른다. 사무실은 터미널 창 없이 시작된다. 선택한 프로젝트의 `.aiorchestra`에 관찰 상태와 문서 기록을 둔다.
3. Codex에 프로젝트 경로와 사무실을 여는 문구가 준비된다. **사용자가 문구를 보내면** Codex가 내장 브라우저에서 사무실 URL을 연다. 공식 `codex://new` 링크는 입력을 준비하며 자동 전송하지 않는다. Codex 설치·로그인은 별도이며, OS가 해당 링크를 처리할 수 있어야 한다.
4. 같은 프로젝트의 실행 중인 사무실이 있으면 그 주소를 재사용한다. 다른 프로젝트/다른 프로그램이 포트를 쓰면 새 포트를 찾는다. 사무실 화면의 **사무실 종료**는 관찰 서버만 종료하고 Codex 작업은 중단하지 않는다.

설치 파일은 서명하지 않은 개발용 빌드다. 설치 동작과 내장 실행 파일 기동을 시험하되, 새 PC의 Codex GUI 첫 연결·OS 보안 경고·조직 정책까지 통과했다고 보장하지 않는다. 사용자 훅 설정/신뢰를 자동 변경하지 않는다. 설치 제거는 설치 파일을 지우며 선택한 프로젝트의 기록은 남긴다.

## 소스에서 실행하는 개발자

Node.js 22.15.1 이상 22.x와 npm이 필요하다.

```powershell
npm run office:setup
npm run office -- --project "D:\MyProject" --port 4539
npm run package:office
```

첫 명령은 고정 의존성과 편집기/TypeScript를 빌드한다. 마지막 명령은 Windows에서 설치 파일을 만든다. 개발 중에는 `npm run build`로 다시 빌드한다. 설치 파일에는 비밀 파일·이 PC의 기록·모델·개발 시험을 넣지 않는다.

## 프로젝트 연결과 실행

```powershell
npm run office -- --project "D:\MyProject" --port 4539
```

- 경로는 실제 존재하는 프로젝트 폴더다. 기본값은 이 저장소 폴더, 기본 포트는 4539다. 읽기·저장은 해당 프로젝트를 대상으로 한다.
- Codex에서도 같은 프로젝트 폴더를 열고 대화를 시작한다. 로컬 Codex 실행 기록에서 같은 프로젝트의 세션만 관찰한다. `CODEX_HOME`을 설정했다면 그 경로의 `sessions`를 사용하며 기본은 사용자 홈의 `.codex/sessions`다.
- 콘솔에 출력된 `http://127.0.0.1:4539/?office=only&source=hooks#office/studio`를 Codex 내장 브라우저에서 연다. Codex에 “이 주소를 내장 브라우저 옆 패널에 열어줘”라고 요청할 수도 있다. CLI 사용자는 일반 브라우저에 같은 주소를 연다.
- 서버 터미널은 켜둔다. Ctrl+C로 종료한다. 포트가 사용 중이면 `--port 4540` 등 다른 포트를 선택한다. 다른 프로젝트는 별도 서버와 포트로 연다.

프로젝트의 `.aiorchestra`에 관찰 상태와 문서 코멘트/저장 접수 기록이 저장된다. 꾸미기와 직원 외형은 브라우저의 프로젝트별 저장소에 저장된다. 가구 설정은 버전 2이며 기존 버전 1을 읽어 보존하고 저장 시 새 키에 기록한다. 다른 브라우저·기기와 자동 동기화하지 않는다. 과거 테스트 협업 DB는 companion 화면에서 읽지 않는다.

## 현재 연결의 정확한 범위

현재 데스크톱 연결은 공식 실시간 세션 SDK가 아니라 **로컬 실행 기록 관찰**을 사용한다. 파일 변경을 구독하고 주기 조회를 보조로 사용한다. 기록 형식 변경·관찰 누락·지연이 가능하다. 상태/활동 메타데이터만 DB에 저장하며, 관찰기는 대화 본문을 DB에 보관하거나 메시지를 보내지 않는다. 선택한 캐릭터의 대화 조회·사용자 전송은 별도의 공식 app-server 연결이 처리한다(ADR 0083). 마지막 수신 상태는 외부 세션이 지금 살아 있다는 보장이 아니다. Codex `token_count`의 세션 누적·최근 호출·이번 실행 차이와 최근 관측 모델을 읽는다. 없는 숫자는 미확인, 시작 기준이 없거나 누적 값이 감소하면 이번 실행은 불확정이다. 캐시 읽기는 입력의 일부, 추론 출력은 출력의 일부이며 중복 가산하지 않는다. 구독 청구액과 직원 성과를 계산하지 않는다. 부모·서브에이전트를 합산하지 않고 각각 표시한다. Claude의 사용량 관찰은 이 Codex 관찰기에 아직 없다.

기존 훅 연결은 별도 경로다. 새 프로젝트/새 훅은 공식 지침대로 정의를 검토하고 신뢰해야 한다. 이 launcher는 사용자 훅 설정을 덮어쓰거나 신뢰를 우회하지 않는다. Claude Code의 신규 프로젝트 자동 탐지는 이 Codex launcher에서 제공하지 않는다.

## 기능 사용

- **사무실 꾸미기:** 화분/스툴/러그와 가져온 가구를 추가한다. 격자에서 선택→이동, 회전, 삭제, 되돌리기, 저장 또는 취소. 기본 책상/회의 테이블/소파/라운지 테이블/탕비대/책장도 맵 드래그 또는 격자로 이동하고 0/90/180/270도로 회전한다. 좌석/경로/착석 위치/깊이 표시가 함께 바뀐다. 벽 이동과 기본 업무 가구 삭제는 지원하지 않는다.
- **잠깐 놀기:** 기억 맞추기(16장/8쌍) 또는 틱택토를 골라 혼자 하거나 `IDLE` 직원 캐릭터와 한다. 기억 게임 상대는 공개된 카드만 기억하며 점수·시도·차례를 표시한다. 실제 직원에게 모델 호출/메시지를 보내는 기능은 아니다. 함께 놀던 직원이 작업 중/완료 확인 대기/목록에서 사라진 상태면 중단된다. IDLE로 돌아오면 이어갈 수 있다. 게임은 페이지 메모리 안에서만 유지된다.
- **문서 보관함:** 실제 파일을 분류해 읽는다. 허용된 문서 폴더의 256KiB 이하 UTF-8 `.md/.txt`는 수정·저장/문서 전체 코멘트를 지원한다. 파일 변경 충돌 시 입력을 보존하고 최신 원문을 불러와 비교한다. 코멘트는 원문 hash와 연결되며 원문이 바뀌면 이전 버전 표시가 나온다. 코멘트가 에이전트 지시로 자동 전송되지는 않는다.
- **내 에셋 팩:** [에셋 제작 규격](OFFICE_ASSETS.md)을 자신의 코딩 에이전트에 전달해 PNG와 JSON을 만들고 가져온다.

## 문제 해결

직원이 없으면 Codex와 launcher의 프로젝트 경로가 같은지, 실행 기록 디렉터리를 읽을 수 있는지 확인한다. 원격 호스트/클라우드 세션은 로컬 파일 관찰로 연결되지 않는다. 연결 거부 화면이면 서버 실행 여부와 콘솔의 포트를 확인한다. 문서 저장 실패 시 입력을 유지한 채 파일 권한과 최신 원문을 확인한다. 꾸미기 저장 실패는 브라우저 저장 공간 부족이나 차단일 수 있다.

## 공식 출처와 구현 구분

- [OpenAI 공식 딥 링크](https://learn.chatgpt.com/docs/reference/commands): 새 대화에 경로/문구를 준비하는 `codex://new`. 문구를 자동 전송하지 않는다.
- [OpenAI 내장 브라우저 안내](https://learn.chatgpt.com/docs/browser?surface=app): 로컬 개발 서버를 실행하고 브라우저에서 열어 나란히 확인하는 흐름.
- [OpenAI 훅 안내](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks): 훅 정의별 검토와 신뢰. 훅 설치가 자동 신뢰를 뜻하지 않는다.

위 출처는 호스트 기능을 설명한다. 이 companion의 파일 관찰 방식·게임·에셋 규격은 프로젝트 자체 구현이며 공식 Codex 확장 API 지원으로 표현하지 않는다.

## Codex 업무 목록과 직원

Codex 전용 사무실의 업무 목록은 현재 관찰된 Codex 직원을 담당자로 사용한다. 일회 업무, 순차 워크플로, 매일/매주/매월 반복 계획을 등록한다. 반복 시간이 되면 업무 레코드를 생성하고 기존 미완료 업무가 있으면 중복 세트를 만들지 않는다. 서버 실행 중에만 일정 확인이 작동한다. **자동 Codex 메시지 실행은 하지 않는다**: 지시 복사 → 담당 채팅 열기 → 전송 → 결과 검토 → 상태 저장을 사용한다. Codex 자동 예약 실행은 화면 상단의 Codex 예약 실행에서 별도로 설정한다.

캐릭터는 원래 Codex 채팅을 열고 직원 명단에서는 외형·이름을 편집한다. 삭제/보관되어 로컬 관찰 원본이 사라진 세션은 맵에서 숨기고 기록은 보존한다. 관찰 파일 존재가 프로그램 접속 상태를 증명하지 않는다. Claude는 현재 Codex 전용 companion 화면에서 제외한다.

사무실 상단의 언어 선택으로 한국어/English를 전환한다. 업무·마케팅·게임·꾸미기·직원/토큰·자료실 UI는 같은 번역 카탈로그를 사용한다. 사용자 작성 내용과 프로젝트 문서는 원문을 유지한다. [마케팅 연결과 실제 범위](SOCIAL_MARKETING.md).


## 사무실 내부 대화

캐릭터 클릭은 오른쪽 대화 패널, 직원 명단 클릭은 설정입니다. 보내기는 공식 codex queue로 원래 Codex 세션에 접수합니다. 작업중 직원도 다음 지시를 접수할 수 있고 서브에이전트는 읽기 전용입니다. 불확실한 전송은 자동 재시도하지 않습니다. 승인과 중단은 원래 Codex에서 처리합니다. 실제 기획자 응답과 같은키 중복 방지를 확인했습니다.

긴 대화는 공식 display summary로 최근6회 사용자·응답만 불러온다. 크기 제한에 걸리면 최근1회 조회로 줄이고 표시 범위를 안내한다. 그래도 너무 길면 전체 대화를 Codex에서 열도록 안내한다. 도구 로그 전체를 사무실 대화 조회에 가져오지 않는다.

독립 client의 thread/resume는 Desktop 소유 세션에서 거절됐으므로 현재 전송에는 사용하지 않습니다. 공식 queue로 원래 소유자에게 전달합니다. 사용자당 한번 설치한 Nookrew 스킬로 어느 로컬 프로젝트에서든 사무실을 열 수 있습니다. 현재 호스트에서 MCP 도구 자동 부착은 확인되지 않아 패키지의 공식 실행 스크립트를 사용하는 스킬 경로를 함께 제공합니다.
